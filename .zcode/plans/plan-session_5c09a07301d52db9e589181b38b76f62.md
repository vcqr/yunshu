# 云书 (yunshu) — MVP 实施计划

## 一、产品范围

局域网传文件/文本工具：启动后常驻系统托盘；点"发送到手机"弹出二维码，手机扫码用**浏览器**打开（零安装）→ 输入 6 位配对码确认 → 双向互传文件和文本。

**本期不做**（架构上预留，后续迭代）：PC↔PC 飞鸽聊天（UDP 发现）、剪贴板自动同步、断点续传、HTTPS、多设备免扫码记忆配对。

## 二、工程结构

会话工作目录 `rsend` 被进程占用、Windows 不允许重命名使用中的目录，因此**工程内命名全部用 yunshu，目录改名留给你以后手动改**（关掉会话后 `ren rsend yunshu` 即可，不影响任何功能）。

```
D:\project\rust-project\rsend\
├─ Cargo.toml              # workspace
├─ .cargo/config.toml      # rsproxy 镜像（同时会配一份全局 ~/.cargo/config.toml）
└─ crates\
   ├─ yunshu-core\         # 无 UI 依赖的业务核心
   │  └─ src\
   │     ├─ lib.rs         # 对外接口：start_server(config, events_tx, ui_rx)
   │     ├─ server.rs      # axum：GET /(手机页) GET /ws(WS) GET /file/:id(下载) POST /upload(上传)
   │     ├─ pairing.rs     # 配对状态机：pending(60s超时) → active；6位码；5次错误限速
   │     ├─ protocol.rs    # WS JSON 消息枚举（serde）
   │     ├─ transfer.rs    # 传输任务表 + 进度事件
   │     ├─ clipboard.rs   # arboard 读写剪贴板
   │     └─ assets\phone.html   # 手机端页面，include_str! 内嵌
   └─ yunshu-desktop\      # bin: yunshu
      └─ src\main.rs       # 后台 tokio 线程 + tray-icon + eframe 主窗口
```

线程模型：tokio runtime 跑在后台线程（网络/传输/剪贴板），eframe 占主线程；两个方向各一条 `std::sync::mpsc` 桥接，core 事件推给 UI 后调 `request_repaint()` 刷新。

## 三、配对与协议设计

- **二维码内容**：`http://<局域网IP>:34256/pair?t=<一次性token>`，token 128 位随机、60 秒刷新，防局域网内他人直连
- **配对状态机**：WS 连上后为 `pending`，只允许 hello/pair 消息；PC 端显示 6 位码，手机输入正确 → `active`；60 秒未确认断开；连错 5 次冷却；`active` 后才有权发文本/文件
- **WS 消息**（JSON）：`hello{name}` / `pair{code}` / `pair-result` / `pc-text{text}` / `send-text{text}` / `pc-file{id,name,size}` / `progress{id,transferred}` / `upload-done{name,size}`
- **文本**：PC→手机为文本卡片+复制按钮（http 下浏览器剪贴板 API 不可用，降级为展示+手动复制，已在设计时确认过的限制）；手机→PC 为 textarea 粘贴发送，PC 收到后写入剪贴板+气泡提示
- **文件**：PC→手机确认后手机端出现文件卡片，点击走 `GET /file/:id` 由浏览器原生下载；手机→PC 网页多选上传 `POST /upload`，PC 弹一次目录选择（rfd）整批保存

## 四、UI 规格（中文）

**托盘菜单**：打开云书 / 发送到手机（=开窗并聚焦二维码）/ ─ / 退出。点窗口关闭按钮=隐藏进托盘，退出只走菜单。

**主窗口**（约 760×540）：
- 顶部状态条：● 服务运行中 · 局域网地址 · [显示二维码]
- 左列（约 300px）：二维码卡片（含倒计时刷新）→ 有 pending 时变为配对码大字卡片 → 连上后变为已连接设备卡（名称/时长/[断开]）
- 右列：传输列表（方向图标/文件名/大小/进度条/状态，完成后可[打开所在文件夹]）
- 底部：[选择文件发送…] [发送剪贴板文本] [设置…]

**手机端页面**（单文件 HTML+原生 JS）：连接页（设备名+6 位码输入）→ 主页（大按钮：发送文件/发送文本；下方"来自电脑"列表：文本卡片+复制、文件卡片+下载）。

## 五、依赖与环境

- `yunshu-core`：axum、tokio、serde/serde_json、uuid、rand、tracing、arboard
- `yunshu-desktop`：eframe 0.37（**default-features=false + glow**，比默认 wgpu 小 2.5MB）、tray-icon、fast_qr、rfd
- 全局 `~/.cargo/config.toml` 配 rsproxy.cn 镜像（你的网络直连 crates.io 超时，本次测试已验证镜像可用）
- release profile：lto + strip + opt-level="z"（实测 glow 后端约 5MB）

## 六、里程碑（每步可编译、可运行）

- **M0** 全局镜像 + workspace 骨架 + 依赖拉通，`cargo build` 通过
- **M1** 桌面壳：托盘图标+菜单、主窗口显示假数据、关闭进托盘
- **M2** 服务上线：axum + 内嵌手机页 + 真二维码（fast_qr→egui 纹理）+ 局域网 IP 显示；**验收：手机扫码能打开页面**
- **M3** 配对：token+6 位码+超时限速；**验收：手机输码成功，PC 显示已连接设备**
- **M4** 文本互发：双向 + 剪贴板集成 + 到达提示
- **M5** 文件互传：下载卡片 + 上传保存 + 传输列表真实数据；**验收：双向传 100MB 级文件**
- **M6** 收尾：设置持久化（TOML：设备名/端口/保存目录）、开机自启（注册表 Run 键）、文案图标打磨、README

每个里程碑跑 `cargo clippy` 保持零警告，最终用真机（手机+PC 同一 WiFi）走完验收路径。

## 七、验收标准

手机扫码 → 输配对码 → PC↔手机互发文本 → 双向传文件，全程手机不装任何东西、PC 不联网（纯局域网）。
