# 云书 · 局域网传书

> 云中谁寄锦书来 —— 局域网内电脑与手机互传文件和文本，手机扫码即用、零安装；电脑之间可远程控制。

云书是一个 Windows/macOS 桌面常驻小工具：启动后缩在系统托盘，点开显示二维码，手机相机扫码在浏览器中打开，输入 6 位配对码完成配对，之后即可双向传输文件和文本。电脑之间通过「飞鸽」模式互发文件/文本/广播，并支持远程控制（屏幕共享 + 键鼠操作）。全程走局域网点对点，不经过任何服务器。

## 功能

- **托盘常驻**：启动即后台服务，点托盘图标打开主窗口；关窗隐藏不退出，退出走托盘菜单
- **扫码配对**：二维码内含 60 秒轮换的一次性 token；6 位配对码二次确认，60 秒超时、5 次错误保护
- **文件互传**
  - 电脑 → 手机：选择文件后，手机网页出现卡片，点击即由浏览器原生下载
  - 手机 → 电脑：网页多选上传，电脑弹窗选择保存目录（2 分钟未选则存默认目录）
- **文本互传**：电脑剪贴板一键发给手机；手机文本以普通消息显示在电脑会话中
- **飞鸽（PC↔PC）**：UDP 广播发现 + Noise XX 加密直连（TOFU 指纹固定），点对点聊天、批量文件传输（断点续传 / 暂停恢复 / 逐文件 SHA-256 校验）、全员广播
- **隐身模式**：开启后停止向局域网广播本机（其他设备的主机列表立即移除本机），也不主动外连；本机主动发送/远程控制不受影响
- **自助添加主机**：设备列表「添加主机」输入 IP:端口 直接建立加密连接，适合对方隐身、跨网段可达或广播不通的场景；手动主机持久化保存、离线也显示在列表，后台每 60 秒自动重连（隐身时不重连），右键可移除。注意：本机隐身时对方看不到本机，需由对方也添加本机才能互相建连
- **远程控制（一期）**：在主机列表点「远程控制」，输入对方**机器 ID + 密码**即可观看并操作对方屏幕（控制端握手后校验对方加密身份与机器 ID 一致，防伪造/中间人）
  - JPEG 帧流约 20fps（画面不变自动跳帧），画质/分辨率可在观看窗口切换
  - 键鼠注入（macOS / Windows），Ctrl/Cmd+V 自动同步本机剪贴板到对方再粘贴
  - 三种密码：临时密码（每次启动随机，设置里可见）/ 固定密码（pbkdf2 加盐哈希落盘，无人值守用）/ 一次性密码（反向协助现场生成，5 分钟有效、用后即焚）
  - 反向协助：列表右键「请求协助控制对方」，对方同意后自动建连，无需手动输密码
  - 安全：密码错误 5 次锁 10 分钟（单 IP 维度），另有跨 IP 全局失败滑动窗口限流（换 IP 绕不过）；被控时托盘图标变红 + 主窗口红色横幅 + 一键断开
  - 观看端为独立窗口（canvas 渲染），支持全屏、F11；关闭窗口即断开
- **传输记录**：进度条、状态、完成后可一键打开所在文件夹
- **设置**：电脑名称 / 端口（默认 34256）/ 保存目录 / 开机自启 / 防打扰（首次启动默认开启）/ 隐身模式，TOML 持久化于配置目录 `~/.yunshu/config.toml`（旧版本系统配置目录的文件首次启动自动迁移）

## 构建与运行

需要 Rust 1.85+（edition 2024）。已配置 rsproxy.cn 镜像（`.cargo/config.toml`，项目级，网络畅通环境可删）。

```bash
cargo run --release
```

产物为单文件 `target/release/yunshu.exe`（约 5 MB，无任何运行时依赖）。

### 前端开发（热重载）

```bash
cd frontend
npm run tauri:dev   # vite 热重载直达桌面窗口（首次为 debug 编译，较慢）
npm run dev         # 仅浏览器预览（无 Tauri 能力，窗口按钮等自动隐藏）
```

注意 Tauri 配置在 `crates/yunshu-app/tauri.conf.json`（非标准 `src-tauri` 布局），`tauri:dev` 已处理好目录跳转；vite 固定 5173 端口（strictPort），被占用时宁可报错也不静默漂移导致白屏。

## 使用步骤

1. 启动云书，托盘出现信封图标
2. 点托盘图标打开窗口，左侧显示二维码和局域网地址
3. 手机（与电脑同一局域网）相机扫码 → 浏览器打开 → 输入电脑上显示的 6 位配对码
   （配对页可切换二维码协议：HTTPS 默认，首次访问需信任自签证书；HTTP 免证书警告，但明文传输，仅建议可信局域网）
4. 互传文件 / 文本

> 注：微信扫码打开时无法下载文件（微信内置浏览器限制），页面会提示——点右上角「···」→「在浏览器打开」后再操作；用系统相机扫码（Safari / Chrome）则无此限制。

## 本机测试（e2e）

`crates/pigeonbot` 是一个无头飞鸽测试节点，可在同一台机器上与云书实例完成 PC↔PC 双向传输的端到端验证（Noise XX 握手、批次邀请、逐文件 SHA-256 校验、暂停/恢复、断点续传）。

```bash
cargo build --release -p pigeonbot   # 构建测试节点

# 终端 1：启动云书主程序
./target/release/yunshu              # Windows 下为 yunshu.exe

# 终端 2：启动测试节点
./target/release/pigeonbot 1048576 60
```

bot 参数：第 1 个为 bot→app 推送批次的测试大小（默认 1MB）；第 2 个为推送完成后保持在线等待 app→bot 来件的秒数（默认 30，拖拽测试建议给大些，传 `0` 表示只测 bot→app 后即退）。

**bot→app 方向**：bot 每 2 秒 UDP 广播，app 飞鸽列表出现"e2e测试节点"并自动连入；握手后 bot 发一条加密聊天 + 三文件批次（1MB / 参数大小 / 0 字节，覆盖空文件与暂停恢复）。在 app 里确认接收后由 app 主动拉取，全部校验通过后 bot 打印 `E2E-BOT-DONE <总字节> <批次id>`，文件落在保存目录。

**app→bot 方向**（测拖拽/右键发送）：在等待窗口内把文件拖进 app 选 bot 发送，bot 无条件自动接受、收块写盘、逐文件校验，完成后打印 `E2E-BOT-RECV-DONE`，文件在 `/tmp/pigeonbot_recv/<批次id>/out/`。

### 单机双开互传

不用 bot，直接开两个云书实例互相传（CLI 覆盖只影响本次运行，不写入 config.toml）：

```bash
# 终端 1（实例 A，默认端口 34256）
./target/release/yunshu

# 终端 2（实例 B，换 HTTP/WS 端口 + 换广播名）
./target/release/yunshu --port 8001 --name 电脑B
```

两个窗口的飞鸽列表都会出现对方（实例 id 每次启动随机生成，必然互相可见；UDP 发现端口支持同机多实例共存：macOS 用 SO_REUSEPORT、Linux/Windows 用 SO_REUSEADDR），选中互发文件/文本即可。给任一实例设 `YUNSHU_AUTO_ACCEPT=1` 可自动接受来件批次，免点确认弹窗。

已知差异（不影响 PC↔PC 互传测试）：HTTPS 34257 只有一个，实例 B 会绑定失败并降级为无 HTTPS（手机端安全上下文功能不可用）；两个实例共享配置目录，静态密钥与信任表相同，互连一般不弹信任确认。

排查：

- 列表能看到节点但连不上——双方约定 id 小者发起连接，bot 只被动接受；bot id 固定来自 `/tmp/pigeonbot_key.bin`，删掉该文件重启 bot 即可换 id
- 换过 bot key 后连不上——app 已 TOFU 固定旧指纹，重置 `known_peers.json`（配置目录 `~/.yunshu` 下，旧版本在系统配置目录）
- 开了防打扰模式会直接拒绝未信任设备，测试时先关掉

纯逻辑单元测试不依赖网络：`cargo test`。

## 远程控制

1. 双方启动云书（同一局域网），主机列表会显示对方（悬停设备行点显示器图标，或右键 →「远程控制…」）
2. 弹窗里确认对方机器 ID，输入对方密码连接。密码来源：
   - **临时密码**：对方「设置 → 远程控制」里展示的 8 位字母数字（无易混淆字符，每次启动重新生成；侧栏点眼睛图标查看）
   - **固定密码**：对方设置里配置的长期密码（无人值守场景，配合开机自启）
   - **一次性密码**：由「请求协助」流程自动生成回传，无需人工输入
3. 观看窗口内直接操作；顶栏可切画质（流畅 720 / 高清 1080 / 超清 1920）、
   切显示器（多屏下拉）、传文件（按钮或直接把文件拖进窗口）、全屏、断开

**视频编码自适应**：默认 H.264（Baseline，SPS/PPS 随关键帧内联），观看端通过 WebCodecs
硬解（WebView2 / Safari 16.4+ 均支持）；观看端不支持 WebCodecs 或出错自动回退 JPEG。
编码器抽象成 trait：H.264 优先硬编（macOS VideoToolbox 已落地，Windows
MediaFoundation 计划中），不可用回退 openh264 软编（全平台一致），画面不变跳帧、
链路拥塞丢帧后自动强推关键帧，并按编码耗时/丢帧率在质量 40-80、帧率 12-25fps 间自适应。

**手机只看不控**：观看会话中主窗口出现「手机观看」按钮，扫码即可在手机浏览器查看
受控屏幕（只读凭证独立于控制凭证，接入后视频自动降为 JPEG 保证兼容）。

**文件回传**：观看会话中可把本机文件推给受控电脑，自动接收并校验整批 SHA-256，
存「保存目录/远程回传/」，两端都有进度卡片。

被控端始终醒目可见：托盘图标变红、tooltip 显示控制方名称、托盘菜单「断开远程控制」、
主窗口红色横幅，均可一键断开。

**机器 ID** 是静态公钥指纹前 8 位 hex（跨重启稳定），主界面侧栏（点眼睛显示）与「设置 → 远程控制」里可查看。凭机器 ID + 密码即可控制，密码在 Noise 加密通道内传输且控制端会校验通道身份与机器 ID 一致；连续输错 5 次锁定 10 分钟，并设跨 IP 全局限流。

**无人值守自启**：
- Windows：设置里「开机自启」为注册表 Run 键（登录后启动）；「系统服务自启」安装
  SYSTEM 服务（管理员授权），开机即启动并在用户登录后自动在会话内拉起云书
  （agent 崩溃 30 秒自动重启）。
- macOS：设置里「开机自启」写入 `~/Library/LaunchAgents/com.yunshu.desktop.plist`
  （登录后启动）。配合固定密码即实现无人值守。

平台权限（一期范围：登录后场景）：

| 平台 | 采集 | 键鼠注入 | 说明 |
|---|---|---|---|
| macOS | 需「屏幕录制」授权 | 需「辅助功能」授权 | 系统设置 → 隐私与安全性；开发期 ad-hoc 签名每次重编译后可能需重新授权 |
| Windows | 无需 | 无需 | 用户态看不到 UAC 弹窗/锁屏/安全桌面 |
| Linux X11 | 无需 | 无需（XTEST） | Wayland 采集走 portal、注入需额外授权，以实际可用为准 |

排障：`cargo run -p yunshu-core --example xcap_smoke` 可单独验证采集权限与编码链路。

## 防火墙提示

首次运行 Windows 会弹窗询问是否允许访问网络，**务必允许**（专用网络）。若错过弹窗，手动放行（启动时固定监听 3 个端口）：

```powershell
netsh advfirewall firewall add rule name="yunshu-http"  dir=in action=allow protocol=TCP localport=34256
netsh advfirewall firewall add rule name="yunshu-https" dir=in action=allow protocol=TCP localport=34257
netsh advfirewall firewall add rule name="yunshu-disc"  dir=in action=allow protocol=UDP localport=34255
```

- TCP 34256：HTTP（手机配对/传输页面 + PC↔PC 飞鸽与远程控制 WebSocket）
- TCP 34257：HTTPS（自签证书，手机浏览器安全上下文）
- UDP 34255：飞鸽发现广播（不放行则互相发现不了）

远程控制不新增端口：视频/输入走 34256 上的独立 `/remote-ws` 加密连接（与飞鸽文件链路隔离，互不挤占）。

若发现"手机打不开页面"，先查：① 防火墙规则；② 路由器是否开启了 AP 隔离/访客网络；③ 电脑是否连了 VPN 虚拟网卡。

## 已知限制（MVP）

- 手机链路为纯 HTTP 局域网明文传输，配对码 + 一次性 token 防蹭连；PC↔PC（飞鸽/远程控制）全链路 Noise 加密
- 手机浏览器剪贴板 API 需要 HTTPS 安全上下文，因此手机→电脑发文本用页面内粘贴的降级方案；电脑→手机的文本用"展示 + 手动复制"
- 手机上传暂不支持断点续传（PC↔PC 批次传输已支持）
- 手机端同一时间只允许一台设备连接
- 远程控制仅登录后场景（看不到 UAC/锁屏/安全桌面）；Windows 服务化可在登录前拉起
  会话代理，但锁屏画面本身仍不可见
- 远程控制 H.264 在 Windows 上为 openh264 软编（macOS 已走 VideoToolbox 硬编），
  MediaFoundation 硬编按 encoder trait 接入中
- macOS 免登录（LaunchDaemon + 锁屏可见）受登录窗口上下文 TCC 限制，不做

## 技术栈

Rust workspace：

- `crates/yunshu-core` — axum（HTTP + WebSocket）、配对状态机、传输管理、飞鸽（Noise XX 加密直连）、远程控制（xcap 采集 + openh264/jpeg-encoder 编码 + enigo 注入 + WebCodecs 解码）、arboard 剪贴板
- `crates/yunshu-app` — Tauri 2 壳（窗口/托盘/命令桥 + Windows 服务化），前端 Vue 3 + Tailwind（`frontend/`）
- `crates/pigeonbot` — 无头飞鸽测试节点（e2e）

线程模型：tokio runtime 跑在后台线程，Tauri 占主线程，`std::sync::mpsc` 双向桥接事件与 UI 请求。
